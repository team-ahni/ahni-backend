# 주전공 졸업요건 입력

## 승인한 범위

2026-11-25 사용자 제공 HWP 5종과 대화에서 확인한 기준으로 2022~2026학번의 단일 주전공 정책 23건을 입력합니다. 반도체산업융합학과는 자료가 있는 2024~2026학번만 포함합니다. 복수·부전공의 기준은 이번 입력에 포함하지 않습니다.

모든 정책의 총학점은 126, 전공 최소학점은 65입니다. 2022~2024학번 교양은 40이며, 2025학번부터는 전공기초 15를 전공 65와 **별도**로 두고 교양은 25로 입력합니다. 이는 앞선 '전공 65 안에 포함' 검토안을 수정하여 원문 표대로 진행하겠다는 사용자 확인을 반영합니다. 잔여 21학점은 별도 필수 분류가 아니라 총학점까지 남는 부분입니다.

승인 데이터와 출처 HWP의 SHA-256은 `data/graduation/2026-11-25/primary-policies.json`에 기록했습니다. 과목 마스터는 수정하거나 새로 만들지 않습니다. 실행 SQL은 같은 폴더의 `import.sql`입니다.

## 스키마와 API

V35는 `graduation_requirement`에 `min_foundation_credit`(기존 정책 기본값 0), `evaluation_complete`(기존 정책 기본값 true), `policy_details`(jsonb)를 추가합니다. V35는 데이터 입력을 수행하지 않습니다. 데이터 입력은 환경별 기존 과목을 확인한 후 별도 트랜잭션으로 실행합니다.

새 정책의 전공기초 학점은 공개된 학과·수강연도 교과과정의 MAJOR_FOUNDATION 연결로 계산하며 전공 학점에 다시 더하지 않습니다. 총학점은 성적의 실제 취득학점을 한 번만 셉니다. 기존 정책의 전공기초 최소학점이 0이면 기존 전공 인정 계산을 유지합니다.

관리자 요청은 선택적 minFoundationCredit를 받습니다. 등록에서 생략하면 0, 수정에서 생략하면 기존 값을 유지합니다. 조회 응답은 minFoundationCredit와 evaluationComplete를 추가하고 진행률은 credits.foundation과 evaluationComplete를 추가합니다. 판정 미지원 상태는 관리자 수정으로 해제되지 않습니다.

## 조건부 규칙의 처리

개별 필수과목으로 확실히 지정할 수 있는 배정 246건만 required_course에 넣습니다. 영어 후보 3개나 핵심교양 후보 6개를 모두 필수로 넣지 않습니다. 과목별 원 필수·선택·대체·면제 규칙과 출처, 미확인 사항은 정책별 policy_details에 보존합니다.

이번에 입력하는 23개 정책의 evaluation_complete는 모두 false입니다. 영어 택1, 핵심교양 A/B 경로, 세부 교양 학점, 대체·면제·시행 시점 판정은 아직 자동화되지 않았습니다. 이에 따라 requirementsMet는 학점이나 등록된 개별 과목을 충족해도 true가 되지 않으며, 앱과 관리자 화면에 추가 조건 확인 안내를 표시합니다. 이 값은 기준이 잘못되었다는 뜻이나 학과의 공식 졸업 불가 판정이 아닙니다.

- 핵심교양: 지정 6과목 중 4과목·12학점 또는 서로 다른 GED 영역의 4과목·12학점. 소융 24학번부터의 영역 방식은 GED2·3·5·6으로 제한합니다.
- 반도체 SEC4001은 HWP에 없어 졸업필수에 추가하지 않습니다.
- 금융 BNF2505는 사용자 확인에 따라 BNF2501 오기 추정으로 기록합니다. 2026-1의 BNF2605 대체 규칙과 원 학번별 목록은 별도 보존합니다.
- 반도체 옛 계열교양 SEG2001·SEG2005는 두 DB의 과목 마스터에 없어 pendingRequirements로 남기고 임의 과목을 생성하지 않습니다.
- 금융·산업경영·반도체 영어의 중급·고급 인정 범위와 메카 24학번 세부 교양 적용, 소융 재수강 표의 불완전한 학수번호 등은 자동 보정하지 않습니다.

## 적용·검증 기록

로컬 개발 DB에는 V35와 같은 스키마 변경을 적용했고, 운영 Supabase에는 Flyway V35를 적용해 전체 이력을 검증했습니다. 두 DB 모두 기존 졸업요건·필수 배정이 0건임을 확인한 뒤 각각 정책 23건과 고정 필수과목 배정 246건을 트랜잭션으로 입력했습니다. 다른 public 테이블의 행 수는 변경 전후 동일합니다. 기존 성적·과목·교과과정·강의는 수정하지 않았습니다.

import.sql은 대상 학과나 고정 과목이 없거나 분류가 맞지 않으면 실패합니다. 기존 대상 정책이 있으면 덮어쓰지 않고 실패합니다. 재실행 전에 동일 배치 기록을 확인해야 하며 임의 삭제·재입력하지 않습니다. 개발 프로필은 Flyway를 사용하지 않으므로 로컬의 Flyway 이력을 수동 생성하지 않습니다.

검증은 GraduationProgressCalculatorTest(전공기초 중복 합산 차단), GraduationProgressServiceTest(미지원 조건에서 전체 충족 차단), GraduationRequirementManagementServiceTest(구버전 수정 시 별도 학점 보존), PrimaryGraduationPolicyImportIntegrationTest(PostgreSQL 실제 입력·재입력 차단)와 세 저장소의 scripts/verify로 수행했습니다.

운영 서버를 실행하거나 배포할 때는 V35를 지원하는 백엔드를 함께 반영해야 합니다. 기존 백엔드가 새 정책의 evaluation_complete를 무시하지 않도록 DB 데이터만 반영한 채 구버전 서버를 계속 사용하지 않습니다.
