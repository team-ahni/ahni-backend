# 연도별 교과과정 적용 가이드

> 성적 등록 조회·검증은 이후 학기별 개설 강의 기준으로 변경되었습니다. 이 문서의 성적 등록 관련 설명은 기존 설계 기록이며, 졸업요건의 교과과정 인정 규칙은 유지됩니다.

## 구현 범위

`curriculum`은 학과·교과과정 연도·출처·공개 상태·편집 버전을 저장하고, `curriculum_course`는 기존 과목을 연결합니다. 기존 course/student_grade의 ID와 FK는 변경하지 않습니다. 권장 학년·학기는 안내이며 수강 제한 조건이 아닙니다.

- 관리자: `/api/v1/admin/curricula`에서 초안 생성·전체 편집, `/{entityId}/publication`에서 공개 상태를 변경합니다. 관리자 매핑 검증은 모든 요청에서 실행됩니다.
- 수정·공개 요청에는 조회한 `version`이 필수입니다. 충돌은 `409 CURRICULUM_EDIT_CONFLICT`이며 새 자료 생성은 version=null입니다. 학과·연도는 생성 후 고정됩니다.
- 학생: `GET /api/v1/curriculum-courses?academicYear=2024`로 공개된 해당 연도의 과목만 조회합니다. 학과 필터는 교과과정 소유 학과에 적용하며 공통 과목은 중복 제거합니다.
- 성적 신규 등록 및 수강 연도 변경은 공개 연결을 검증합니다. RPL도 예외가 없습니다. 과거 비활성 과목은 공개된 해당 연도에 연결되어 있으면 허용합니다.
- 같은 연도 기존 성적의 등급·학점 수정은 교과과정 누락을 이유로 막지 않습니다. 기존 성적 삭제와 평점 계산도 유지합니다.
- 교과과정 수정은 전체 연결을 교체하고 비공개 초안으로 돌아갑니다. 실패하면 원래 공개 상태와 연결을 보존합니다.

## 공통 전공과목 인정

같은 학수번호는 하나의 `course`를 여러 학과·연도의 `curriculum_course`에 연결합니다. `course.department`는 선택적인 관리 소속이며 인정 학과를 제한하지 않습니다. 전공과목도 관리 학과 없이 생성할 수 있습니다. 과목 영역과 연결 분류의 일치 검증, 중복 연결 방지, 관리자 검증과 편집 잠금은 유지합니다.

졸업요건 정책은 여전히 **학과·입학년도·전공유형**으로 선택합니다. 전공 이수학점은 **학과·성적 수강연도·과목 ID**가 모두 일치하는 공개 연결만 인정합니다. 관련 학과와 수강연도의 연결은 요청당 한 번 일괄 조회하며 추가 캐시는 사용하지 않습니다. 초안·삭제 학과·다른 연도 연결과 관리 소속만으로는 인정하지 않습니다. 기존 성적은 총학점·GPA에 유지하고, 재수강 대체를 먼저 적용한 뒤 전공별로 집계합니다. 전공별 안내 합계를 합산하여 복수전공 중복 인정 정책으로 사용하지 않습니다.

V20은 `ck_course_major_department`만 제거합니다. 기존 ID·FK·학수번호 고유성·분류 제약과 데이터는 보존합니다. Flyway 관리 DB는 새 버전을 적용하고, Flyway가 꺼진 로컬 DB는 백업 후 같은 SQL만 한 트랜잭션으로 적용합니다. 이미 적용한 V11은 수정하지 않습니다. 공통전공 입력은 이 스키마 변경 후 진행합니다.

공개 변경·편집은 교과과정 배타 잠금, 성적 저장은 공유 잠금을 사용합니다. 같은 연도의 자료를 ID순으로 잠그며 성적 저장까지 트랜잭션을 유지합니다. 과목 연결을 만드는 동안은 후보 과목 공유 잠금, 과목 수정은 배타 잠금을 사용합니다. 연결된 과목의 학과와 분류는 변경할 수 없습니다.

목록은 연결과 과목을 일괄 조회합니다. 추가 캐시·Redis·파티셔닝은 없습니다. 선택한 연도 변경·초안 저장·재공개 직후에 이전 캐시가 남지 않도록 요청 단위 조회를 유지합니다.

## DB 적용 전에 확인할 사항

2026-10-07 사용자 승인 후 로컬 ahni_dev와 공유 Supabase에 신규 스키마 및 RLS를 적용했습니다. Supabase는 Flyway V17에서 V18·V19를 한 트랜잭션으로 적용해 생성 직후의 미보호 노출을 피했습니다. 로컬은 Flyway 비활성 설정을 유지하고 동일한 신규 SQL만 트랜잭션으로 적용했습니다. 이후 소융 2024·2025·2026 전공 자료와 연도별 공통교양을 비공개 초안에 입력했습니다. 출처·건수·확인 보류 사항은 [공식 학사 자료 입력 내역](../../data/academic/README.md)을 참고합니다.

1. 기존 DB를 백업하고 연결 대상·Flyway 이력·현재 스키마를 확인합니다. 비밀값은 화면 캡처나 커밋에 포함하지 않습니다.
2. Flyway가 V17까지 관리하는 DB는 V18(테이블)·V19(RLS)를 적용합니다. 두 파일을 한 번에 적용할 때는 한 트랜잭션으로 묶습니다. dev의 `ddl-auto=update`는 Flyway 적용 증거가 아닙니다. JPA가 이미 새 표를 만든 DB에는 V18을 중복 실행하지 말고 제약·기본값·이력을 먼저 비교합니다.
3. 기존 migration 전체 재실행, DROP, Docker volume 삭제, 기존 성적 FK 변경을 하지 않습니다. 이미 적용한 migration 파일을 수정하지 않습니다.
4. 신규 표의 Supabase Data API 노출·GRANT·RLS와 Spring JDBC 역할을 확인해야 합니다. JWT 관리자 검증은 Data API 직접 접근을 보호하지 않습니다. 이번에는 JDBC postgres 역할의 BYPASSRLS를 확인한 뒤 승인받아 신규 두 표에만 V19 RLS를 활성화했습니다. anon/authenticated에 허용 정책을 추가하지 않았으며, 실제 역할별 조회·쓰기 차단과 백엔드 접근 유지를 롤백 검증했습니다. 기존 테이블 권한·RLS는 변경하지 않았습니다. 향후 JDBC 역할을 변경한다면 새 역할에서도 서버 접근이 유지되는지 먼저 검증합니다.

적용 전 public 스키마·데이터 백업은 Git에서 제외되는 `.env.backups/yearly-curriculum-2026-10-06-B1JLdi/`에 각각 보관했습니다. 파일 권한은 600이며 PostgreSQL 18 복구 도구로 읽기와 주요 테이블 포함을 확인했습니다. 실제 복원은 하지 않았습니다. 기존 8개 테이블의 적용 전후 행 수·데이터 해시는 동일합니다.

## 공식 자료 입력과 배포 순서

기존 클라이언트가 전체 과목을 조회하므로 서버 검증만 먼저 배포하면 성적 등록이 실패할 수 있습니다. 우회 flag나 다른 연도 fallback은 추가하지 않습니다.

1. 관리자 교과과정 API와 새 표를 먼저 준비하되 기존 성적 저장 검증은 아직 전환하지 않습니다. 배포를 분리할 경우 조회/관리 API와 GradeService 검증 변경을 별도 릴리스로 나눕니다.
2. 공식 과목을 기존 과목 관리에서 등록합니다. 같은 학수번호가 이미 있으면 재사용하고, 같은 이름·다른 학수번호는 별도 과목으로 유지합니다. 학점·이름 불일치는 원본을 확인하며 자동 덮어쓰지 않습니다.
3. 관리자 **교과과정 관리**에서 학과·연도·출처를 입력하고 기존 과목을 연결합니다. 권장 이수, 영역, 비고를 원본과 대조해 초안으로 저장합니다.
4. 제공된 소융 자료의 67개 학수번호와 기본 149개 연결을 대조합니다. 공통교양 추가 후 소융 초안의 연결 수는 2024년 211개, 2025년 264개, 2026년 255개입니다. 공학인증·외국인 전용 자동 연결 보류와 공식 리포트 표시 건수 차이는 자료 manifest 및 입력 내역을 확인합니다. 비활성 과목 연결은 해당 연도의 원본에 있을 때만 허용합니다.
5. 출처·과목 확인 체크와 공개 확인을 거쳐 자료를 공개합니다. 누락된 교양을 추정해서 만들지 않으며 부분 입력을 완비된 자료라고 보고하지 않습니다.
6. 새 모바일 클라이언트와 공개 자료가 준비된 다음 서버의 성적 연도 검증을 전환합니다. 이 브랜치 전체를 한 번에 배포한다면 위 준비를 배포 전에 끝내야 합니다.

## 확인 시나리오

- 2024 선택 시 2025 전용 코드는 목록에 없어야 합니다. 같은 이름이어도 코드가 다른 과목을 섞지 않습니다.
- 연도 변경 시 선택 과목·자동 학점·검색·재수강 선택을 초기화하고 늦은 이전 응답은 무시합니다.
- 미등록/비공개 연도는 `CURRICULUM_NOT_AVAILABLE`로 안내합니다. 다른 연도 과목 저장은 `COURSE_NOT_IN_CURRICULUM`입니다.
- 기존 같은 연도 성적 수정, RPL, 재수강, GPA를 회귀 확인합니다. 시뮬레이터·실기기 확인은 사용자가 수행합니다.

다중전공 합격 시점(작업 B)과 영어 선택·핵심교양 A/B·대체 과목(작업 C)은 이번 작업 A에 포함하지 않았습니다. 영어 3개 과목을 모두 필수로 지정하거나 A/B를 혼합 판정하지 않습니다.
